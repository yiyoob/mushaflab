## D67: Architecture reset: the qirāʾāt as farsh, uṣūl and writing conventions; the patch model frozen
Status: accepted (Yusuf and Eisa, 2026-11-23; relayed by Eisa)
Date: 2026-11-23
Context: The first build (Phases 0–8, D1–D66) stored each riwāyah as codepoint edits against the
Ḥafṣ spine, derived by diffing the KFGQPC texts: 82,582 raw patches for Warsh, 31,906 of them only
an encoding convention, 50,676 `unclassified`; the 508 mined "rules" were codepoint patterns with
status `hypothesis`. An edit records what changed, never why, so the data could not be reviewed;
the method needs a published text, so it had no route to the 12 riwāyāt without one; and KFGQPC
prints one wajh per place. Loading ~120 MB of generated YAML made builds and tests slow (15 s to
load, 16 min for `data-verify`, an 81 MB web bundle). Planning doc: "Mushaf Lab: Architecture Reset"
(claude.ai, 2026-11-21/23); canonical summary: `docs/ARCHITECTURE.md`.
Options:
1. Keep the patch model and classify the patches. Keeps the opacity and the dependence on
   published texts; no model for wujūh or their combinations.
2. Rebuild the data model by layer (words, letter features, farsh, uṣūl occurrences, riwāyah
   profiles with wujūh and combination tables, writing conventions, ayah counting, layouts),
   keeping the rendering engine.
3. Start a new repository. Loses the engine, the font work and the tests for no gain.
Decision: 2. Milestones M0–M6 in `PROJECT_PLAN.md` (v3), one PR each, each with a gate. The
patch-model app is frozen (rule 12): it keeps building and rendering the 8 KFGQPC riwāyāt until the
new model reproduces each one, then it is deleted (M3). Kept and moved onto the new model:
`mushaf-shape`, `mushaf-justify`, `mushaf-draw`, `mushaf-layout`, `mushaf-engine`, `mushaf-wasm`,
the web app, the font work, the KFGQPC importers and the book extractors.
Consequences: New work lands in `corpus/`, `core/mushaf-corpus` and `core/mushaf-text`. Gaps that
belong to the patch model are tagged legacy in `known-gaps.md`. PROJECT_PLAN v2 is kept in
`docs/history/`. Task ids change from `T<phase>.<n>` to `M<milestone>.<n>`.
